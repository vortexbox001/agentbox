# Brief 011 — Shell, user settings modal, and tabbed agents list from the delivered mocks

This brief fulfils the placeholder text of 011 ("Page rebuild from mocks") in `specs/000-briefs-revised.md`: the mocks have now been delivered inside the design system, so the screen-specific acceptance criteria are written here. It is presentation and shell work on top of completed 009 (design system) and 010 (file layout). No agent schema field changes; the two new data reads (latest runs, asset checks) are read-only calls to Dagster's existing GraphQL API. The shared contracts in `000-briefs-revised.md` apply (paths, missing data is unknown not zero, Dagster owns run state).

## Intent

Make the served management UI match the updated design system in three places: (1) the left navigation and its foot, (2) a user-settings modal that replaces the inline theme control, and (3) the agents page rebuilt as the tabbed full-bleed list with the new column set. After this, every served page uses the revised shell; the agents page answers "what is each agent, when does it run, how did it last go, did its checks pass" at a glance; and the design-system copies of `app.css`, `dropdown.js`, and `icons.svg` are no longer ahead of what is served.

## What changes

### 1. Sidebar and foot (all pages, `ui/templates/base.html`, `ui/static/shell.js`)

- **Primary nav.** Items are 32px rows as today. A `.ax-nav-divider` keyline separates nav groups. Only pages that exist get a link: `Agents` and `Automation` (below the divider, as the "objects" group). The mock's `Overview` and `Runs` entries belong to 012/023 and are **not** rendered as dead links or disabled placeholders; the divider is kept so the group lands where the mock puts it. See open question Q1.
- **Foot, top to bottom.** (a) The Dagster status block (`.ax-dagster`), now styled with the indigo translucent fill and indigo text in every theme (it is a Dagster-branded element, so it keeps Dagster's colour). Behaviour unchanged: dot state ok/down/unknown polled as today, opens Dagster in a new tab. (b) A keyline (`.ax-foot-links` top border). (c) `Hide navigation` foot link with the collapse icon: replaces the `Collapse` toggle; same persistence (`agentbox.sidebar`), same 68px collapsed rail; when collapsed only the icon shows, rotated, and its accessible name becomes `Show navigation`. (d) `Settings` foot link with the gear icon: opens the user settings modal.
- **Theme control removed from the foot.** The three-button radiogroup and its test (`test_theme_control_is_accessible_icon_buttons`) go; the equivalent assertion moves to the modal's dropdown.
- **Collapsed rail.** Foot links centre their icons and hide labels; the brand shows the mark only; nothing overflows the 68px column. The `.ax-dagster` block keeps its dot only.

### 2. User settings modal (`ui/templates/base.html` + a `settings` partial, `ui/static/shell.js`)

- **Chrome.** Rendered through the `dialog` macro into `#ax-modal-root` (the same root the confirm modal uses), `role="dialog"`, `aria-modal`, `aria-label="User settings"`. New modal chrome per the DS: square corners, `--color-background-default` surface, header `User settings` and the actions row carry full-bleed 2px keylines, body padding between them. This chrome change also restyles the existing confirm/dirty-form modal; that is intended.
- **Content.** One section, `Preferences`, heading in `--type-display-sm`, one row `Theme` with a dropdown on the right (13rem). Actions row: a single primary `Done` button. There is no Save: choosing a theme applies immediately and persists immediately; `Done`, Escape, and a backdrop click all just close.
- **Theme dropdown.** The `select` macro enhanced by `dropdown.js`, options carrying `data-icon`: `Light` (`theme-light`), `Dark` (`theme-dark`), `Dagster Indigo` (`theme-dark` icon per the mock), `Use system setting` (`theme-system`). The trigger shows the current option's icon as the lead glyph (`.ax-dropdown-lead`). Keyboard: Tab to trigger, Enter/Space opens, arrows move, Enter selects, Escape closes the panel without closing the modal, a second Escape closes the modal.
- **Theme semantics.** Preference stored in `localStorage["agentbox.theme"]` ∈ {`light`, `dark`, `indigo`, `system`}; the pre-paint script in `base.html` must resolve all four and stamp `data-theme="dark"` or `data-theme="indigo"` or remove the attribute for light. `system` keeps today's behaviour (follow `prefers-color-scheme`, live update on OS change) — the mock's "default to dark unless the OS says light" is equivalent in practice and is not a required change. The indigo theme is dark neutrals with Dagster's indigo accent replacing teal (`theme.css` already maps `--color-accent-teal`, links, focus ring, checkbox, brand gradient). Anything in `app.css` that hard-references a teal core token rather than an accent alias must be checked so indigo actually swaps the accent (the schedule-pill checked track already targets `--color-core-indigo500`; decide whether that is theme-invariant by design).
- **Focus.** Focus moves into the modal on open and returns to the `Settings` foot link on close; Tab cycles inside the modal while it is open.
- A `config/settings.yaml` theme setting is still out of scope (localStorage only, as 009 decided).

### 3. Agents page as the tabbed list (`ui/templates/agents/list.html`, new `ui/static/agents-list.js`, `ui/agents_store.py`, `ui/dagster.py`, `ui/main.py`)

Based on `TabbedList.dc.html`. The page has **no page header**: `list.html` overrides the `page_header` block and renders `.ax-list-view` directly under `.ax-main`, replacing `.ax-content` padding. The page title stays in `<title>`.

- **Tabs** (`.ax-list-tabs`, `tabs` macro with counts): `All`, `Assets`, `Jobs`, `Scheduled`, `Disabled`. Counts are computed server-side from the agents store: Assets = agents with `produces.asset`, Jobs = agents with `job: true` (an agent that is both counts in both), Scheduled = agents with at least one cron (asset or job schedule) regardless of Dagster on/off state, Disabled = `enabled: false`. Tab choice filters rows client-side, is reflected in the URL (`?tab=assets`) so it survives reload and can be linked, and defaults to `All`.
- **Toolbar** (`.ax-list-toolbar`): left group `Filter` (outlined, filter icon) and a `Show disabled agents` checkbox; right group the primary `New agent` button (moved here from the page header). `Show disabled agents` defaults off; when off, disabled agents are hidden from every tab except `Disabled`; the choice persists in localStorage. `Filter` reveals an inline text field that narrows visible rows by substring over name, harness, and model; empty field = no filter. See Q2 if a placeholder is preferred instead.
- **Table** (`table` macro with `full_bleed=true`, edge to edge, horizontally scrollable inside `.ax-list-view` when narrower than its columns; the sidebar's collapse gives it room). Rows sorted by name. Columns, in order:
  1. **Name** — mono link to the edit page. The existing `name mismatch` badge and the parse-error row treatment (error badge + message spanning the data columns) are preserved.
  2. **Harness** — mono text (no longer a badge).
  3. **Model** — mono text, truncated with ellipsis and full value in `title`.
  4. **Kind** — `asset` badge (`.ax-badge--asset`), `job` badge (`.ax-badge--job`), both when both.
  5. **Schedules/Sensors** — one `schedule_pill` per configured cron: `clock` icon for a job schedule, `sensor` icon for an asset schedule (the macro's hard-coded `automation` icon is replaced by a `type`-driven icon). Label is the human-readable cron (`Every day at 7:00 AM`) in the box's `TZ`, using one shared cron-to-text helper that the Automation page can reuse. The compact toggle reflects Dagster's instigation state (running/stopped) for that schedule or sensor and flips it through a new `POST /api/agents/{name}/triggers/{kind}` that calls Dagster's start/stop mutation; the toggle is disabled with an explanatory `title` when the agent is disabled, when Dagster is down, or when the state is unknown. On-demand agents show `—`. See Q3.
  6. **Latest run** — `status_dot` + relative time (`2 hours ago`, `running now`); the text links to that run in Dagster. `—` when no run is known or Dagster is unreachable.
  7. **Checks** — for asset agents with declared checks: one result icon per check from the latest materialization, `check-circle` green for pass, `warn-tri` yellow for a failed non-blocking check, `x-circle` red for a failed blocking check (`error`/`timeout` count as failed), grey for not yet run; four per row, wrapping; `title` carries check name and status. `—` for agents without checks.
  8. **Run history** — the last ten runs as bars, newest at the right, green success / red failure / neutral for empty slots or in-progress; each bar's `title` is the run's status and time. This column is present by default (the mock's `showRunHistory` prop is not a user toggle).
- **Removed from the page.** The `Status` column (enabled/disabled is now the row style + tab + checkbox) and the `Dagster` column (the `runs` button). The per-agent Dagster deep link survives in the Latest-run and Run-history cells; the edit page keeps whatever Dagster link it has.
- **Empty and error states.** The existing "No agents yet" card stays for an empty store (rendered inside the list view below the toolbar). When Dagster is unreachable, columns 5–8 degrade to `—` / disabled toggles and the page shows the DS `alert` (warning) `Run data unavailable: Dagster is not reachable`; the page never fails to render because Dagster is down.
- **Data path.** Page render stays server-side. A new `GET /api/agents/activity` returns, for all agents in one call, per-schedule instigation state, latest run (id, status, start/end), the last ten run statuses, and latest-materialization asset-check results; it is fetched by `agents-list.js` after first paint and fills columns 5–8 (columns 1–4 come from the store at render time and never wait on Dagster). The endpoint issues a bounded number of GraphQL requests (target: one aliased query, never one per agent), has a short timeout, and returns `null` fields (unknown) rather than guessing. Naming follows `agents_store.dagster_job_path`/`dagster_asset_path` so the run lookup is by the same job name / asset key the factory registers.
- **Automation page.** Unchanged in function. It gains nothing new except reuse of the cron-to-text helper and the icon change in `schedule_pill`; its toggles remain the existing cron editors.

### 4. Design-system sync (`ui/static/`, `ui/design-system/`, tests)

- `ui/static/app.css`, `ui/static/dropdown.js`, and `ui/static/icons.svg` are brought up to their `ui/design-system/static/` counterparts. The DS copies resolve icons in-document (`<use href="#id">`) and reference `../../static/` paths; the served app uses `/static/icons.svg#id`. The spec picks one mechanism and records it. Recommendation: inline the sprite once in `base.html` and make `dropdown.js` icon refs document-relative, then the two `dropdown.js` files become identical and `app.css` differs only by its header comment. Add a test that fails when the served file and the DS file diverge beyond the documented substitution, so the DS cannot silently run ahead again.
- Icons missing from the sprite are added: `filter`, `settings`, `check-circle`, `warn-tri`, `x-circle`, `overview`, `runs` (the last two so the nav can adopt them later without a sprite change).
- The `schedule_pill` macro gains a `type`-driven icon (`clock`/`sensor`); the `select` macro passes through `data-icon`/`data-note`/`data-filter` on options and the select; the `tabs` macro renders `.ax-tab-count`. `_ds_manifest.json` is unchanged, so `test_each_manifest_component_has_a_macro` needs no new macro; the DS `Dropdown` card is a form of `Select`.
- The mocks use inline `style` attributes for placeholders (`—` colour, link colour, list reset); the served templates must not (constitution VII, `test_no_inline_styles_in_app_templates`). Every such value becomes a class in `app.css` on tokens: `.ax-cell-empty`, the mono link colour, the list reset on `.ax-dropdown-list`.
- `readme.md` gains short sections for the tabbed list view, the settings modal, the foot links, and the indigo theme; the DS `index.html` specimen gallery already shows the indigo scale.
- Housekeeping: `ui/design-system/AgentBox Design System.zip` is the imported bundle and is not committed; `screenshots/` are committed as the mock reference; `_adherence.oxlintrc.json` changes are DS-internal and stay as delivered. `github.md` is the DS project's sync log and is left as delivered.

## What I'd check

- Every page (agents list, new/edit form, automation, 404) in light, dark, and indigo: foot shows Dagster block, keyline, `Hide navigation`, `Settings`; no theme buttons in the foot; collapse to 68px and back with no overflow; the collapsed foot link's accessible name reads `Show navigation`.
- Open Settings, pick `Dagster Indigo`: accent, links, focus ring, checkbox tint, and the primary button all go indigo without reload; reload keeps it; pick `Use system setting`, flip the OS theme, the UI follows. Escape once closes the dropdown panel, Escape again closes the modal, focus lands back on the `Settings` link. The dirty-form confirm modal shows the new square keylined chrome.
- Agents page against `indigo.png` at 1280 and at a viewport narrower than the table: tabs with correct counts, toolbar, full-bleed table with the eight columns, horizontal scroll inside the list view only, sidebar still pinned.
- With the example config: an agent with both `asset` and `job` shows two Kind badges and two pills; an on-demand agent shows `—`; a disabled agent is hidden until `Show disabled agents` or the `Disabled` tab; `?tab=scheduled` reloads onto the Scheduled tab.
- Flip a pill toggle: Dagster's schedule page shows it running; flip back; stop Dagster, reload: pills disabled with a title, Latest run / Checks / Run history show `—`, the warning alert appears, columns 1–4 still render.
- Run an asset agent with one passing and one failing non-blocking check (the 008 example): Checks shows a green and a yellow icon with the check names in `title`; the Run history bar for that run is green; a failed job agent's bar is red and its Latest run text links to the run in Dagster.
- Parse-error agent and name-mismatch agent rows render as before inside the new table.
- Test suite: the conformance tests pass on the new tree and still fail on an inserted literal; the new sync test fails when `ui/design-system/static/app.css` is edited without `ui/static/app.css`; the theme assertion now targets the modal dropdown; every `<select>`, `<button>`, `<table>` in rendered pages still carries its DS class; an inline `style` in `list.html` fails the build.
- Block egress and reload: fonts, icons, and the sprite render; no request leaves the box.

## Out of scope

Overview and Runs pages and their nav entries (012/023). Editing cron expressions from the agents table (Automation keeps that). A theme setting in `config/settings.yaml`. Server-side persistence of tab/filter/checkbox choices. Run detail pages, transcript viewing (012). Sensors beyond the asset-schedule instigator Dagster already registers. Rebuilding the agent form or automation page beyond the shared macro and icon changes. Mobile layout. Porting `AgentsList.dc.html` (superseded by the tabbed list for the agents page).

## Null action

If Dagster's GraphQL cannot return latest runs and asset-check results for all agents within a bounded request, ship columns 1–5 live and render columns 6–8 as `—` with the warning alert text `Run data unavailable`, recording the limitation in the plan; do not scan run directories on disk to fake the data. If the start/stop mutation cannot be authorised or is unreliable, render the pill toggle as a disabled, state-reflecting control with `title="Turn on from Dagster"` and keep the Automation page's "starts paused, turn on from Dagster" wording. If the four-way theme cannot be resolved before first paint without a flash in some browser, keep the three-way resolution and treat `indigo` as `dark` in the pre-paint script only, then correct after `shell.js` loads.

## Open questions for `/speckit-clarify`

- **Q1 Nav contents.** The sidebar mock lists `Overview`, `Runs`, divider, `Agents` and omits `Automation`. Assumption here: render `Agents` and `Automation` below the divider and add `Overview`/`Runs` when their pages exist. Alternative: keep `Automation` reachable only from the agents page (pill or link) and drop it from the nav now.
- **Q2 Filter button.** Assumption: a working inline text filter. Alternative: a clearly marked non-interactive placeholder until a richer filter (harness/kind facets via the DS filterable dropdown) is designed.
- **Q3 Live schedule toggles.** Assumption: the pill toggle starts/stops the Dagster schedule or sensor (new write endpoint). Alternative: read-only state display; the toggle is disabled and points to Dagster. This is the only behaviour addition in the brief.
- **Q4 Run history length and source.** Assumption: ten most recent runs of the agent's Dagster job (asset agents: runs that materialized the asset), newest right. Confirm whether partitioned asset agents should show per-partition history instead.
- **Q5 Indigo theme scope.** Assumption: a third theme selectable by the user. Alternative: indigo is only for the Dagster status block and is not offered as a page theme.
